# Ticketing v1.1 — Round 2 Refinement Tasks

> Previous implementation round did not match the intended design. This round has explicit Figma references for most tasks — **before implementing any task that has a Figma link, use the Figma Dev Mode MCP to fetch the actual design context (get_design_context) for that node ID first.** Do not guess layout, spacing, or field order from text description alone — verify against the fetched Figma node, then implement to match it. Work through tasks in order. After finishing each task, check it off below, briefly summarize what changed, and note any place where you couldn't fully match the Figma reference (and why) before moving to the next task.

---

- [x] **1. Restructure Board page layout — main tabs, filter row, view switcher**
  - Figma reference: `https://www.figma.com/design/cqWBSETJx8198NvlBS2y1y/INDY-Phase-4?node-id=166-6081` (layout structure of board view)
  - Main tabs: "Board" / "Archive"
  - Filter row: Search input + a filter dropdown/select with values "My Task" / "All Ticket", placed beside the search. Both search and filter should be the same small size, following shadcn's small size convention.
  - View switcher (Grid / List / Kanban) is only available under the **Board** tab.
  - The **Archive** tab only supports **Grid** and **List** views (no Kanban).

- [x] **2. Archive badge label**
  - In the Archive view, the status badge shown on each ticket should display the label **"Archive"** instead of the underlying status label.

- [x] **3. "My Tasks" filter logic**
  - Confirm/implement: the "My Task" filter (from Task 1's filter dropdown) shows only tickets where the current mock user is the `author`, the `issueOwner`, or listed in `pic[]`. "All Ticket" shows everything (respecting the current Board/Archive tab).

- [x] **4. New Kanban ticket card component**
  - Figma reference: `https://www.figma.com/design/cqWBSETJx8198NvlBS2y1y/INDY-Phase-4?node-id=166-6109` (card component)
  - Board view reference (full context): `https://www.figma.com/design/cqWBSETJx8198NvlBS2y1y/INDY-Phase-4?node-id=162-7368`
  - Build/restructure the ticket card used in Kanban to match this Figma component.
  - Hide the status badge on the card itself — status is already conveyed by the Kanban column header, so it's redundant on the card.
  - Add a severity/priority indicator (icon + label, e.g. colored dot or icon for Critical/High/Medium/Low) matching the Figma reference styling.
  - Add a PIC avatar stack (overlapping circular avatars, with a "+N" overflow indicator if there are more PICs than can be shown) to represent assigned PIC(s).
  - This new card should be used consistently in Grid view too, not just Kanban, unless the Figma reference shows a different card for Grid — check and confirm.

- [x] **5. Create Ticket form — align with Figma modal reference**
  - Figma reference: `https://www.figma.com/design/cqWBSETJx8198NvlBS2y1y/INDY-Phase-4?node-id=167-9120`
  - Top of form: radio group with title **"On Whose Behalf Is This Ticket?"**, options **"By Myself"** / **"On Behalf of Someone Else"**.
  - When "By Myself" is selected: no extra field shown, `issueOwner` defaults to current user.
  - When "On Behalf of Someone Else" is selected: show a **"Who owns this ticket?"** select field below the radio group, for picking the target user (`issueOwner`).
  - Below Issue Category group: add **Domain** select (options: "NDM AL", "NDM SL").
  - Below Domain: add **Table Name** field — combobox with suggested options, but also accepts free text.
  - Add **PIC** field — multi-select combobox.
  - Add **Priority** select — Critical / High / Medium / Low.
  - Match the exact field order and layout shown in the Figma reference (two-column vs single-column groupings, spacing) rather than stacking everything in one column.
  - Keep the existing IP Address field, unchanged.

- [x] **6. Detail page — restructure info block**
  - Figma reference: `https://www.figma.com/design/cqWBSETJx8198NvlBS2y1y/INDY-Phase-4?node-id=171-9307`
  - Add to the ticket info block: **Domain**, **Table Name**, **Priority**, **PIC** (as an avatar stack, same style as the Kanban card).
  - Match field order/layout to the Figma reference.

- [x] **7. Detail page — edit mode**
  - Clicking "Edit" enters an edit state for these fields only: **Status**, **Domain**, **Priority**, **PIC**.
  - For PIC in edit mode: user can remove existing PICs and add new ones (multi-select behavior, not just display).
  - Avatar stack (both in detail page and Kanban card) should show a tooltip listing all PIC names on hover, especially useful when the stack is truncated with a "+N" indicator.
  - While in edit mode, the "Edit" button becomes a **"Save"** button.
  - The Save button should be **disabled** if no field value has actually changed from the original.
  - Provide a **Cancel** button next to Save, which discards changes and exits edit mode without saving.

- [x] **8. Save confirmation toast**
  - After clicking Save (with at least one changed field), show a toast notification confirming the ticket information was successfully updated.

- [x] **9. Closure flow confirmation**
  - Confirm existing behavior still holds after all the above changes: clicking "Submit Close & Archive" opens the **Ticket Closure & Resolution Details Form**. On successful submit, the ticket status becomes `closed` and the ticket appears in the Archive tab.
